# Taskと会議の操作

FocusのTaskカードは「操作」から、状態・対応予定日・その他の3群を開きます。ドラッグを8px以上動かすと「ここにドロップ」が現れ、同じ利用可能な操作を選べます。その他は折りたたみ表示です。

|対象|状態|対応予定日|その他|
|---|---|---|---|
|次にやる・予定|開始、完了|今日やる、日付を選ぶ、予定日なし|期限、詳細編集|
|計測中|中断、完了|なし|期限、詳細編集|
|完了済み|続きのTaskを作る|なし|期限、詳細編集|

開始は既存の計測開始・切替手順、中断と完了は既存の作業終了手順を使います。別のTaskが計測中なら、切替内容を選ぶ前に現在の実績は変わりません。未開始Taskを完了しても、架空の開始・終了時刻は作りません。完了済みの通常Taskは「続きのTaskを作る」から、今日やる・日付を選ぶ・予定日なしをコピー先として選べます。

計測済みTaskの実績編集は既存の「実績を編集」ボタンから行います。Taskの完了取消は提供しません。続きTaskは既存の中断と同じ `continuation_of` で元のdone Taskを参照します。元Taskの実績・外部ID・依存解除は保持し、コピーへはタイトル・本文・Project／Area・期限・Context・見積・自身の依存だけを引き継ぎます。実績・Calendar identity・NX対応ID・元の通知停止設定は引き継ぎません。コピー先の選択をキャンセルすると、元Taskも新規Taskも変わりません。結果不明時は既存の照合を行い、コピーを再作成しません。終了Projectなど新規Taskを置けない対象はエラーを表示し、自動的にリンクを外したりProjectを再開したりしません。予定時刻を変更する新しい操作は追加していません。予定Taskの日付移動は既存の開始・終了の時刻と日跨ぎ間隔を保持します。

メニューと日付選択のキャンセル、Escape、対象外へのドロップは書込みを行いません。依存で開始できないTaskには理由を表示し、開始ドロップを提供しません。保存結果が不明・回復待ちなら操作を停止して既存の照合を使います。

会議は操作メニューから完了・完了取消・実績調整を選びます。カード本体とグリップは実績区間全体を動かし、上下の端は開始・終了を調整します。ボタンや端の操作は本体ドラッグを開始しません。予定と実績は分離され、再取込で手動実績を上書きせず、Undoで実績操作を戻せます。

## ローカル検証

合成データだけでNode契約テストとUI回帰を実行します。

```sh
python -m unittest tests.test_task_operations_runtime tests.test_outlook_import tests.test_webapp_guard tests.test_webapp_pwa
node tests/focus_action_date_runtime.js
python tests/run_task_operations_ui_e2e.py --output /tmp/task-operations-qa
python tests/run_outlook_import_ui_e2e.py --output /tmp/outlook-qa
```

UI回帰はPlaywrightが利用可能な環境で、ループバックサーバーと新規headlessブラウザーを使います。Taskは1280・390・320px、会議は1280・390pxで確認します。会社接続・実績の外部送信を行いません。
