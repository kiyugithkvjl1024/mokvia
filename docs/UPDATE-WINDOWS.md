# 会社PCで新版ZIPへ更新する

会社PCは公開済みソースの取得だけを行います。会社データ・変更した会社コード・ログをGitHubや個人環境へ送信しません。Gitへのログイン、clone、pushは更新に不要です。会社Copilotは会社が許可した機密情報を扱えますが、その許可を公開Issueや個人環境への搬出へ広げません。

この手順はmokviaからmokviaへの更新用です。旧名のvolume・Windows状態が検出された場合は起動・バックアップ・復元を停止して保存先を示します。自動移行や削除は行いません。

## 更新手順

1. 更新先の公開commitまたはrelease、変更点、データ互換性、成功したCIを確認します。追跡できない「最新」ではなく版を固定してください。
2. **旧版フォルダーで** `windows/Backup.ps1` を実行します。アプリは停止したままになり、バックアップは会社承認済みのソース外フォルダーへ保存されます。取得完了を確認してください。
3. 公開repoの指定版ZIPを取得し、旧版へ重ねず新しいソース用フォルダーへ展開します。会社が保存・ダウンロードを許可した場所を使います。会社データやバックアップをコピーしません。
4. 新版フォルダーで `windows/Start.ps1` を実行します。固定Compose project `mokvia` とvolume `mokvia_data` を再利用します。フォルダー名を変えてもデータ用volume名を変えません。
5. localhostでTask/Project/Reviewの件数と代表記録、予定・実績、通知を確認します。バックアップ取得と旧版ソースは受入完了まで保持します。

`docker compose down -v`、volume削除、Docker resetを更新に使いません。取得したコードを会社で変更している場合は、Copilotに変更差分をローカルで確認させ、新版への適用範囲を決めてください。会社固有の差分を公開repoへアップロードしません。

## 戻す場合

データ形式に変更がなく、更新後の記録を旧版が読めることを確認できる場合は、新版をStopし旧版をStartします。互換性がない/不明な場合は自動で戻さず、必要な更新後の記録を会社内で保全してから、旧版ソースと更新前バックアップを使います。復元は更新後の記録を置き換えるため、その範囲を確認します。

通常の更新ではMarkdown形式を維持します。形式変更が必要な版は、移行・復元手順と互換性を明示するまで導入しません。実際のWindows通知・スリープ復帰・会社ポリシーへの適合は更新後も会社PCで受入確認します。

## Copilotへの更新指示

> この会社PC内でmokviaを指定された公開版ZIPへ更新してください。docs/UPDATE-WINDOWS.mdを読み、旧版で停止バックアップしてから別フォルダーへ展開し、同じCompose project/volumeで起動・読戻ししてください。会社ルールで許可された機密情報は会社Copilot内で扱えます。会社データ・会社コード・ログを公開repoや個人環境へ送信せず、Git push、自動逆同期、会社ポリシー変更を行わないでください。互換性が不明なら更新を止めて具体的な差分を示してください。
