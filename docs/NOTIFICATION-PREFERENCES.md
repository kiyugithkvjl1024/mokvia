# 通知設定

Focus画面の末尾にある「通知設定」を開きます。「指定時間帯は通知OFF」を選び、開始・終了、必要ならIANAタイムゾーン（例 `Asia/Tokyo`）を入力して「通知設定を保存」を押します。開始は含み、終了は含みません。22:00–08:00のような日跨ぎを扱います。同時刻の開始・終了は受け付けません。

タイムゾーン空欄は通知処理を実行するOSのローカル設定です。会社版のDockerではコンテナーのOS設定で、Windowsホストと一致するとは限りません。確実に日本時間で使う場合は `Asia/Tokyo` を指定してください。存在しないIANA名やパスは拒否します。IANA名は実行環境のzoneinfoデータを使用します。`Asia/Tokyo` はzoneinfo未同梱でも日本標準時（UTC+09:00）として利用できます。他のIANA名は対応するzoneinfoデータが必要です。

「Focus督促」「Focus状態異常」「休憩終了」を個別にOFFにできます。Focus状態異常には進行中Taskなし、複数doing、開始時刻未記録・未来、監視API契約エラー・会社版監視失敗が含まれます。既存Focus時間windowとTask単位の通知OFFはそのまま適用します。初期値は時間帯OFFを無効、全種類ONです。

個人版の既存Slack通知と、会社版の既存Windows・ブラウザー通知に適用します。通知の権限取得や送信の設定は行いません。休憩終了の通知を抑制しても、休憩Taskは所定の終了時刻で自動完了します。抑制した通知は破棄し、quiet終了後にまとめて配信しません。quiet中に期限が到来した休憩を翌朝処理した場合も通知を破棄します。翌朝の新しいFocus監視tickは通常どおり評価します。

設定は非秘密ファイル `.local-state/notifications/settings.json` にatomic保存され、再起動後も保持します。会社版のbackup/restoreにも含めます。保存APIはOrigin・Web marker・revisionを検証し、競合や結果不明時は再送せず保存状態を読み直します。複数画面から変更した場合は最新の保存状態を確認して操作してください。壊れた設定ファイルは通知を抑止し、休憩完了処理を止めません。画面の「保存状態を再読込」は書き込みません。

## ローカル検証と制限

合成データ・偽Slack transport・一時loopback HTTPだけで、境界時刻、日跨ぎ、種別、revision競合、送信直前抑止、休憩完了と再送禁止を検証します。実Slack送信、実資格情報、会社ネットワーク、実Windows Balloon/ブラウザーOS通知、Docker Desktop実機でのOSタイムゾーンはこの変更の検証対象外です。通知がOFFでも既存のOS通知許可設定は変えません。

会社版Windows・ブラウザーは、`local-notifications` を取得する時点で設定とquietを評価します。取得後、OSが表示するまでの遅延でquiet開始や設定変更を跨ぐ可能性は残ります。取得時に抑制されたイベントは破棄し、後から再表示しません。OS側の表示キュー・既に表示した通知の取消は対象外です。

## 承認後の反映と設定変更

個人版への初回反映ではWebサービスを再起動し、常駐している休憩schedulerが稼働中ならそのサービスも再起動して新しいコードを読み込みます。Focusは既存のoneshotで次回tickから新コードを使うため、timerの時刻・資格情報・通知先は変更しません。会社版は既存の停止backup→新版別フォルダー→同じCompose project/volumeで起動の更新手順に従い、アプリcontainerを新版へ更新します。Windows通知workerは既存Start/Stop手順で管理します。ブラウザーは再読込して新しい設定画面を読み込みます。

導入後も初期状態は従来どおりの通知です。夜間OFFを使う場合は本人が時間帯OFFを有効にし、22:00–08:00と必要なタイムゾーンを保存します。以後の設定保存は再起動不要で、通知処理が最新設定を都度読みます。新しい資格情報、OAuth、通知権限、timerの追加・変更は不要です。正常な通知抑制はサービス失敗ではなく正常終了として記録します。
